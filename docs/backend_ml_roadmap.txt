План развития проекта: сервер + ML + интеграция с Android

1. Поднять backend-проект отдельно
- Создать папку backend/
- Выбрать стек: Python + FastAPI
- Добавить базовую структуру:
  - backend/app/
  - backend/app/api/
  - backend/app/services/
  - backend/app/models/
  - backend/data/
  - backend/ml/
- Сделать первый технический endpoint:
  - GET /health

2. Подключить сервер к приложению без ML
- Настроить в Android запросы к backend
- Сначала сделать тестовый endpoint:
  - GET /predict/mock
  - или GET /routes
- Проверить, что приложение получает JSON с сервера
- Только после этого убирать локальные заглушки постепенно

3. Описать API-контракт
- Определить, что Android отправляет на сервер:
  - route_id
  - direction_id
  - stop_id
  - day_of_week
  - time
  - weather
- Определить, что сервер возвращает:
  - occupancy_percent
  - seat_status
  - forecast_10
  - forecast_20
  - forecast_30
  - forecast_60

4. Подготовить backend к работе с маршрутами и остановками
- Научить сервер читать:
  - routes_2gis.json
  - stops_2gis.json
- Нормализовать маршруты, направления и остановки
- Подготовить внутренние модели данных для backend

5. Сгенерировать synthetic dataset
- Написать Python-скрипт генерации датасета
- Использовать реальные маршруты, направления, порядок остановок и траектории
- Сгенерировать признаки:
  - route_id
  - direction_id
  - stop_id
  - stop_index
  - total_stops
  - hour
  - weekday
  - is_weekend
  - weather
  - interval_minutes
  - active_buses_count
  - route_length
  - distance_from_start_ratio
- Сгенерировать target:
  - occupancy_percent

6. Обучить первую ML-модель
- Базовая модель: CatBoostRegressor
- Обучать вне Android, на backend/Python стороне
- Сделать train/validation split
- Посчитать базовые метрики:
  - MAE
  - RMSE
- Сохранить модель в файл

7. Встроить модель в backend
- При старте сервера загружать обученную модель
- Сделать endpoint:
  - POST /predict
- Сервер получает признаки и возвращает прогноз
- На сервере переводить occupancy_percent в seat_status

8. Подключить реальный прогноз в Android
- Переделать экран ForecastScreen
- Вместо локальной эвристики запрашивать backend
- Показывать ответ модели для выбранного маршрута, остановки, дня, времени и погоды

9. Подключить аналитику к backend
- Часть аналитики перенести на сервер
- Сервер может отдавать:
  - загрузку по часам
  - самые загруженные остановки
  - сводку по времени
- Android только отображает готовые данные

10. После этого улучшать качество
- Улучшать synthetic dataset
- Добавлять больше признаков
- Сравнить CatBoost с LightGBM/XGBoost
- При появлении реальных данных переобучить модель уже на них

Правильный порядок работ
1. Сначала backend без ML
2. Потом связь Android <-> backend
3. Потом synthetic dataset
4. Потом CatBoost
5. Потом endpoint прогноза
6. Потом интеграция прогноза в приложение
7. Потом аналитика через backend

Ближайший следующий шаг
Создать backend/ и сделать минимальный FastAPI сервер с endpoint /health и /predict/mock.
