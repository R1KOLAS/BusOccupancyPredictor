QalaBus / Bus Occupancy Predictor
Полное описание проекта для дальнейшей работы с ChatGPT и подготовки дипломной записки

1. Общая идея проекта

Проект представляет собой Android-приложение для просмотра автобусных маршрутов, остановок,
карты движения транспорта, прогноза загруженности и аналитики по маршрутам.

Рабочее название и бренд в интерфейсе: QalaBus.

Основная идея:
- пользователь выбирает автобусный маршрут;
- смотрит маршрут на карте;
- видит остановки и имитацию движения автобусов;
- смотрит прогноз загруженности по остановке, дню недели и времени;
- смотрит аналитику по маршруту;
- данные могут работать либо локально, либо через backend.

Проект сделан как дипломный прототип/MVP, но уже имеет:
- Android-приложение;
- backend на Python/FastAPI;
- ML-модель CatBoost;
- SQLite в backend;
- собственный пайплайн подготовки данных.

3. Что реализовано в Android-приложении

3.1. Стартовый экран

Есть стартовый экран приложения с брендом QalaBus.

На стартовом экране:
- иконка/логотип;
- название QalaBus;
- подзаголовок "Прогноз загруженности транспорта";
- карточка с краткими возможностями;
- две кнопки запуска:
  - "Начать" — запуск через backend;
  - "Запуск локально" — работа без backend.

Также добавлен отдельный экран загрузки:
- полноэкранный;
- с вращающимся PNG;
- используется при первом старте и перед входом в основную часть приложения.


3.2. Раздел "Маршруты"

В разделе маршрутов реализовано:
- список всех маршрутов;
- поиск по номеру и описанию;
- открытие детальной страницы маршрута.

На детальной странице маршрута:
- отображается номер маршрута;
- конечные точки;
- карта маршрута;
- список остановок по маршруту;
- кнопки перехода:
  - в карту,
  - в прогноз,
  - в аналитику.

Карта маршрута в деталях уже не является простым прототипом:
- вместо старой условной схемы используется реальный маршрут;
- строится на основе реальных parsed-данных.


3.3. Раздел "Карта"

Это один из ключевых экранов приложения.

Реализовано:
- карта OpenStreetMap через osmdroid;
- выбор города;
- поиск маршрута по номеру или описанию;
- режим "Маршруты";
- режим "Загруженность";
- кнопка геолокации;
- кнопка возврата к выбранному маршруту;
- отображение маршрута на карте;
- отображение остановок маршрута;
- отображение движущихся автобусов.

Особенности карты:
- можно выбрать конкретный маршрут;
- карта умеет центрироваться на маршруте;
- автобусы движутся по траектории маршрута;
- автобусы движутся плавно;
- автобусы останавливаются на остановках;
- автобусы едут туда и обратно;
- количество автобусов зависит от размера маршрута;
- скорость автобусов искусственно настроена для наглядной визуализации;
- при выборе автобуса можно включить отслеживание;
- при ручном движении карты отслеживание отключается.

Режим "Загруженность":
- остановки окрашиваются по уровню загруженности;
- автобусы окрашиваются по цвету следующей остановки по направлению движения;
- цвет автобуса меняется по мере продвижения по маршруту.

Текущие цвета загруженности:
- зелёный — низкая/умеренная загруженность;
- оранжевый — средняя загруженность;
- красный — высокая загруженность.


3.4. Раздел "Прогноз"

Экран прогноза поддерживает:
- выбор остановки;
- выбор дня недели;
- выбор времени;
- выбор погодного условия:
  - дождь;
  - снег;
- отображение текущего значения;
- прогноз на 10 / 20 / 30 / 60 минут;
- нижнюю рекомендацию.

Что важно:
- в backend-режиме данные приходят с сервера;
- в локальном режиме прогноз считается локально;
- если backend-режим выбран и сервер недоступен, приложение пишет, что сервер недоступен;
- локальный fallback в backend-режиме отключён.

Также исправлена логика отображения:
- если выбран не текущий момент, карточка больше не пишет "Сейчас";
- вместо этого показывается выбранный день и время.


3.5. Раздел "Аналитика"

Экран аналитики показывает:
- сводку по времени суток;
- загрузку по часам;
- самые загруженные остановки;
- детальную аналитику по вкладкам.

В детальной аналитике есть вкладки:
- обзор;
- остановки;
- дни.

Аналитика:
- может работать локально;
- может работать через backend;
- в backend-режиме при недоступности сервера локальные данные не подменяются;
- показывается ошибка недоступности backend.


3.6. Нижняя навигация

Нижняя навигация теперь адаптивная.

Логика:
- изначально доступны только "Маршруты" и "Карта";
- после выбора конкретного маршрута появляются:
  - "Прогноз"
  - "Аналитика"

Если выбор маршрута сброшен:
- дополнительные вкладки исчезают.


4. Источник транспортных данных

В проекте использовались страницы 2GIS, сохранённые локально.

Из них были распарсены:
- автобусные маршруты;
- остановки;
- направления;
- координаты остановок;
- траектории маршрутов;
- связи между маршрутами и остановками.

Для этого были написаны Python-скрипты парсинга.

Теперь исходные данные разложены так:
- сырые HTML 2GIS: data/raw/2gis/
- экспортированные результаты парсинга: data/exports/

Основные экспортированные файлы:
- data/exports/routes_2gis.json
- data/exports/routes_2gis.csv
- data/exports/stops_2gis.json
- data/exports/stops_2gis.csv

В Android-приложении используются asset-файлы:
- app/src/main/assets/routes_2gis.json
- app/src/main/assets/stops_2gis.json


5. Backend

Backend расположен в отдельной папке backend/.

Он сделан как самостоятельный проект, чтобы:
- его можно было запускать отдельно;
- не смешивать Android и серверный код;
- проще показывать архитектуру дипломной системы.

Backend написан на FastAPI.

Основные маршруты API:
- GET /health
  - проверка, что сервер работает;
- GET /routes
  - список маршрутов;
- GET /routes/{route_id}/stops
  - список остановок маршрута;
- POST /predict
  - реальный прогноз загрузки;
- POST /predict/mock
  - старая mock-заглушка;
- GET /analytics/{route_id}
  - аналитика по маршруту.

Как работает backend:
- принимает параметры маршрута/остановки/времени/погоды;
- находит нужные данные;
- использует ML-модель;
- формирует ответ;
- возвращает JSON приложению.


6. ML-часть

6.1. Выбранная модель

Для проекта выбрана модель CatBoostRegressor.

Почему выбрана именно она:
- данные табличные;
- много категориальных признаков;
- хорошо подходит для MVP и дипломного проекта;
- проще и логичнее для такой задачи, чем нейросеть.


6.2. Что предсказывает модель

Модель предсказывает:
- occupancy_percent

То есть процент загруженности автобуса/маршрута в конкретный момент.

Дальше backend преобразует процент в статус:
- available
- few
- none

В интерфейсе это показывается как:
- сидячие есть;
- свободных мало;
- сидячих нет.


6.3. Какие признаки подаются в модель

На вход модели подаются признаки, связанные с:
- маршрутом;
- направлением;
- остановкой;
- позицией остановки внутри маршрута;
- днём недели;
- временем;
- погодой;
- интервалом движения;
- количеством автобусов на линии;
- размером маршрута.

Примеры признаков:
- route_id
- route_number
- direction_id
- direction_type
- stop_id
- stop_name
- stop_index
- total_stops
- weekday
- is_weekend
- hour
- minute
- weather
- interval_minutes
- active_buses_count
- direction_platform_count
- direction_path_points_count


6.4. Как генерируется датасет

В проекте используется synthetic dataset.

Он не просто случайный, а rule-based + random variation.

Смысл генерации:
- берутся реальные маршруты и реальные остановки;
- для них искусственно генерируются сценарии времени, дня недели и погоды;
- затем по логике рассчитывается примерная загрузка.

Логика генерации учитывает:
- автобусы начинают ходить примерно с 06:00;
- движение продолжается до 23:00;
- в будни утром 7-9 выше загруженность;
- после 9-10 утра загрузка спадает;
- вечером 17-18 снова пик;
- в выходные пики значительно слабее;
- дождь повышает загрузку;
- снег повышает загрузку ещё сильнее;
- разные маршруты имеют разную чувствительность к пикам и погоде.

Также в генераторе добавлены более контрастные сценарии:
- час пик может давать очень высокую загрузку;
- дневные часы могут быть заметно спокойнее;
- разные участки маршрута имеют разную интенсивность.


6.5. Обучение модели

Для генерации и обучения созданы отдельные скрипты:
- backend/ml/generate_synthetic_dataset.py
- backend/ml/train_catboost.py

Результаты хранятся так:
- synthetic dataset:
  - backend/data/synthetic_occupancy_dataset.csv
- модель:
  - backend/models/catboost_occupancy.cbm
- метрики:
  - backend/models/catboost_occupancy_metrics.json

Служебные логи CatBoost:
- backend/catboost_info/

11. Важные ограничения проекта

Чтобы описание было честным, важно зафиксировать ограничения:

- Данные не приходят из реального транспортного API в режиме реального времени.
- Движение автобусов на карте сейчас является имитацией.
- ML обучается на synthetic dataset, а не на реальных исторических данных перевозчика.
- Погода сейчас задаётся параметром, а не берётся из живого погодного API.
- Прогноз — это прототип интеллектуальной системы, а не промышленная эксплуатационная версия.

Это не является проблемой для диплома, если корректно описать проект как:
- прототип;
- исследовательскую систему;
- демонстрацию архитектуры и подхода к прогнозированию.

13. Краткая формулировка для диплома

Проект QalaBus представляет собой интеллектуальную информационную систему мониторинга
и прогнозирования загруженности автобусных маршрутов. Система включает мобильное Android-
приложение, серверную часть на FastAPI, SQLite-базу данных и ML-модель CatBoost, которая
используется для прогнозирования уровня загруженности по маршруту, остановке, времени и
погодным условиям.
